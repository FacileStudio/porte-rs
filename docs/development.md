# porte-rs — Development

How to build, test and release the crate, and how the Go test vectors stay in step.

## Prerequisites

- Rust 1.98 or later (`rust-version` in `Cargo.toml`), with `rustfmt` and `clippy`
- Docker and `pg_isready` (psql 16 or later), for the scratch Postgres the database tests use
- `filet` 0.18 or later, and `lefthook` through `mise install`
- A sibling checkout of `tronc-rs` at `~/Code/Facile/tronc-rs` with its tag `v0.2.0`: until the
  repos are pushed, `Cargo.toml` reads it through a `file://` git URL

## Setup

```sh
mise install
mise run db-up
export TEST_DATABASE_URL='postgres://postgres:test@127.0.0.1:5652/postgres?sslmode=disable'
```

`db-up` starts `postgres:16-alpine` on `127.0.0.1:5652` and returns once `pg_isready` answers.
`mise run db-down` stops it. Run the tests only after `pg_isready` succeeds: a test that
connects while the server is still starting fails with `UnexpectedEof` rather than skipping.

## The gate

```sh
sh scripts/check.sh
```

It waits for `TEST_DATABASE_URL` to accept connections, then runs `cargo fmt --check`,
`cargo clippy --all-targets --all-features --locked -- -D warnings`,
`cargo test --all-features --locked`, then `filet check .`. `mise run check` calls the same
script, and `lefthook` runs it on pre-push. Without `TEST_DATABASE_URL` the database tests print
a skip banner and pass, so read the output before trusting a green run.

Each feature must also build alone:

```sh
cargo clippy --all-targets --no-default-features -- -D warnings
for f in pg oidc; do
  cargo clippy --all-targets --no-default-features --features "$f" -- -D warnings
done
```

## Tests

| File | Covers |
|---|---|
| `tests/conformance.rs` | Every case in `tests/vectors/*.json`, generated by Go `porte` |
| `tests/session.rs`, `tests/session_issue.rs` | Issue, expiry, the idle window, touch coalescing, binding, logout |
| `tests/origin.rs` | `Manager::check_origin` |
| `tests/oidc_flow.rs`, `tests/oidc_cli.rs`, `tests/oidc_claims.rs`, `tests/oidc_profile.rs`, `tests/oidc_provision.rs` | The whole kit against an in-process fake provider (`tests/common/provider.rs`) that enforces PKCE, the redirect URI and client authentication |
| `tests/registre.rs` | Boots a kit against a live Registre; skipped unless `REGISTRE_ISSUER_URL` is set |
| `tests/pg_sessions.rs`, `tests/pg_identities.rs` | The `pg` stores against Postgres |

`tests/migrations/0001_porte.sql` is the migration an app ships: `porte::pg::SCHEMA` verbatim,
and a test fails when the two drift. Every database test binary migrates its own schema and
uses fresh ids, so the tests run in parallel without truncating.

Discovery against the real issuer is a read-only GET:

```sh
REGISTRE_ISSUER_URL=https://sso.facile.studio cargo test --all-features --test registre
```

## Vectors

The vectors are Go `porte`'s `conformance/vectors/*.json` and the keys in
`conformance/testdata/`. Every file has the envelope `{"source","subject","cases"}`.
`tests/vectors/SOURCE` names the tag and commit they came from, and a test fails when a file
names another.

```sh
sh scripts/sync-vectors.sh ~/Code/Facile/porte-wt-vectors v0.16.1
```

The script reads the checkout with `git show`, so it never touches its working tree.

## Versioning

Tags are `vX.Y.Z`, cut locally. While on `v0`, a breaking change bumps the minor. Record each
release in `CHANGELOG.md` before tagging. Consumers pin a tag in their `Cargo.toml`.
